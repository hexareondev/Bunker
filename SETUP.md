# БункИИр — техническая инструкция

Статический сайт для GitHub Pages + Firebase Realtime Database (бесплатный план Spark, без привязки карты).

## Возможности

- Лобби по 4-символьному коду или ссылке, список игроков с индикатором «онлайн».
- Переподключение: закрыли вкладку или перезагрузили страницу — откройте ту же ссылку, и вы вернётесь в игру на то же место.
- Настройки перед стартом (только у хоста): играет ли хост, число мест, диапазон возраста, чёрный юмор, сколько характеристик раскрывать в раундах, с какого раунда голосовать, тайное голосование, правило ничьей, карты действий, таймеры на каждый этап (0 — без таймера, переход вручную).
- Раунды: игроки говорят по очереди и раскрывают характеристики → общее обсуждение → голосование → итог. Если игрок не успел раскрыть характеристику до конца таймера, она раскроется автоматически.
- Карты действий применяются игроками напрямую: замена и обмен характеристик, разоблачение, иммунитет, двойной голос, саботаж голосования, +1 место, разведка бункера, возвращение изгнанного и др.
- Панель хоста: следующий этап, пауза, +30 сек, раскрыть или заменить любую характеристику любому игроку, изгнать или вернуть, передать права хоста, завершить игру, сбросить в лобби.
- Финал: история выживания с учётом катастрофы, бункера и характеристик выживших (включая, смогут ли они продолжить род).
- Если хост отключился, таймеры продолжает вести первый подключённый игрок.
- Табло на общий экран: `index.html?board=КОД` — подписывается на комнату только для чтения, в `players` не пишет, таймеры не ведёт. Озвучка может читаться только на табло (`narration: "board"`). QR-коды рисует `js/qr.js` (генератор `js/vendor/qrcode.mjs`, MIT).
- Экран не гаснет во время игры (Screen Wake Lock API), вибрация на важные события (Vibration API).
- Личные настройки игрока (⚙️): тема оформления (`css/themes.css`, атрибут `data-theme` у `<html>`), звук и громкость. Хранятся в `localStorage` (`bunker.prefs`). Звуки синтезируются в браузере через Web Audio (`js/sfx.js`), аудиофайлов нет. Озвучка текста — встроенный синтез речи браузера (Web Speech API, `js/tts.js`); кто читает, задаёт настройка лобби `narration` (host / all / off).

## Настройка (один раз, ~10 минут)

### 1. Firebase

1. Зайдите на https://console.firebase.google.com → **Add project** (Google Analytics можно выключить).
2. Слева **Build → Realtime Database → Create Database**. Регион — например, `europe-west1`. Режим — **locked mode**.
3. На вкладке **Rules** базы вставьте содержимое файла `firebase-rules.json` и нажмите **Publish**.
4. Шестерёнка → **Project settings** → внизу **Your apps** → значок `</>` (Web) → зарегистрируйте приложение (Hosting не нужен).
5. Скопируйте объект `firebaseConfig` и вставьте его в `js/firebase-config.js`. Проверьте, что там есть `databaseURL`. Если его нет, скопируйте адрес базы со страницы Realtime Database.

`apiKey` в веб-конфиге Firebase не секретный, его нормально хранить в публичном репозитории.

### 2. App Check (защита базы от чужих запросов)

1. В Firebase Console откройте **Security → App Check → Apps**, выберите веб-приложение и провайдер **reCAPTCHA Enterprise**. Там будет ссылка на Google Cloud Console (раздел **Fraud Defense**).
2. В Google Cloud Console (тот же проект, что и Firebase) откройте **Fraud Defense**, при необходимости включите API и создайте ключ:
   - тип **Web**;
   - домен `hexareondev.github.io` (`localhost` в этот ключ не добавляйте);
   - галочку «Use checkbox challenge» **не** ставьте.
3. Скопируйте ID ключа и вставьте его в Firebase (шаг 1) → Save.
4. Тот же ключ впишите в `appCheckSiteKey` в `js/firebase-config.js` и закоммитьте.
5. Поиграйте пару раз и проверьте в **App Check → APIs → Realtime Database**, что запросы помечены как verified.
6. Нажмите **Enforce** для Realtime Database.

Карта оплаты не нужна: на бесплатном плане Spark работает, просто доступно меньше уровней оценки риска.

Для локальной проверки на `localhost` откройте консоль браузера: там появится отладочный токен App Check. Добавьте его в **App Check → Apps → ⋮ → Manage debug tokens**.

### 3. GitHub Pages

1. Создайте новый репозиторий и загрузите в него все файлы проекта (папки `content`, `css`, `js`, файлы `index.html`, `firebase-rules.json`, `README.md`).
2. **Settings → Pages → Build and deployment → Source: Deploy from a branch**, ветка `main`, папка `/ (root)`.
3. Через минуту сайт будет доступен по адресу `https://<ваш-логин>.github.io/<репозиторий>/`.

### Локальная проверка

Из-за загрузки JSON страницу нельзя открыть двойным кликом, нужен локальный сервер:

```
python -m http.server 8000
```

и откройте http://localhost:8000. Чтобы изобразить несколько игроков, используйте разные браузеры или режим инкогнито.

## Как добавлять контент

Проще всего — через встроенный редактор: `editor.html` (ссылка внизу главной страницы). Он загружает текущие JSON, даёт их редактировать и выгружает архив, в котором лежит папка `content/` со всеми файлами. Распакуйте архив в корень репозитория с заменой и закоммитьте. Вручную файлы можно править так же — формат описан ниже.

Каждая характеристика лежит в своём файле в папке `content/`:

| Файл | Что внутри |
|---|---|
| `professions.json` | профессии (стаж добавляется автоматически) |
| `biology.json` | пол и особенности; возраст генерируется из диапазона в настройках |
| `health.json`, `hobbies.json`, `phobias.json`, `baggage.json`, `facts.json`, `characters.json` | остальные характеристики |
| `catastrophes.json` | катастрофы: `title`, `text`, `duration` и `months` — срок в месяцах для расчёта еды (`null`, если неизвестен) |
| `bunkers.json` | особенности бункера; `foodMonths` — сколько месяцев еды добавляет (или отнимает, если число отрицательное); `"foodInfinite": true` — бесконечная еда, перекрывает любую нужду |
| `conditions.json` | состояние бункера: `text`, `desc` |
| `tags.json` | проблемы для финала (см. ниже) |
| `actions.json` | карты действий |

### Поля для финала

У любой карточки (характеристики, особенности бункера) могут быть:

```json
{ "text": "Кошка", "desc": "Ловит крыс…",
  "needs":  { "morale": 1 },        // вклад в нужды: food, medicine, repair, defense, morale, reproduction (−2…+2)
  "solves": ["rodents"],            // какие проблемы решает
  "weak":   ["roaches"],            // к каким проблемам уязвим
  "causes": ["infection"] }         // какие проблемы вызывает
```

У катастроф и состояний бункера `needs` означает, насколько сильно они бьют по нужде: в файле это число 0…2 (важность), а редактор показывает его со знаком минус (0…−2), потому что катастрофа нужду занижает. `causes` — какие проблемы они создают.
`"onlyByCard": true` — значение не раздаётся при старте, его выдают только карты действий (например, «Полностью здоров (исцелён)»).

Проблемы описаны в `tags.json`:

```json
{ "id": "rodents", "icon": "🐀", "name": "Грызуны", "need": "food", "power": 1, "foodLoss": 4, "deadly": false,
  "solved": "Крысы переловлены, припасы целы. Заслуга: {who}.",
  "unsolved": "Крысы грызли мешки с крупой — часть припасов пропала.",
  "weak": "{name} не выносил(а) соседства с крысами." }
```

`need` и `power` — по какой нужде и насколько сильно бьёт нерешённая проблема, `foodLoss` — сколько месяцев еды пропадает, `deadly` — уязвимые погибают. Формы вроде «(а)» подставляются по полу персонажа. Старое поле `"food": 1` по-прежнему понимается (как `needs.food`).

Формат записи характеристики:

```json
{ "text": "Кошка", "desc": "Ловит крыс и может помочь с депрессией.", "dark": false }
```

`"dark": true` — чёрный юмор; такие записи не выпадают, если в настройках выключен чёрный юмор.

`"food": 1` — характеристика помогает с едой (значок 🍖 еда), `"food": -1` — требует больше еды (🍖 −еда).

`"desc"` — необязательное описание: показывается мелким текстом под значением на карточке, в карточке раскрытия и в списке особенностей бункера. Работает для всех характеристик и для `bunkers.json`.

В `biology.json` первая часть до запятой — пол (`Мужчина` / `Женщина`), всё после запятой — дополнение. Слово «бесплод…» в дополнении учитывается в финальной истории.

Карта действия:

```json
{ "id": "find_bag", "icon": "🎁", "title": "Находка на складе",
  "text": "Добавьте себе в багаж одну вещь на выбор из трёх случайных.",
  "effect": { "type": "change", "op": "add", "object": "trait", "key": "baggage",
              "target": "self", "mode": "pool_choice", "pool": { "source": "random", "size": 3 } },
  "dark": false }
```

Поле `onlyByCard: true` у значения характеристики или особенности бункера — оно не выпадает при раздаче и в случайном выборе карт; получить его можно только картой действия с заданным списком (`pool.source: "preset"`) или конкретным значением (`mode: "fixed"`). Если у эффекта стоит `withCardOnly: true`, случайный выбор этой карты тоже может дать такие значения.

Случайные исходы: у любой записи с финальными полями может быть `variants: [{ weight?, note?, needs?, solves?, weak?, causes? }]`. В финале для каждой карточки выбирается один исход (с учётом `weight`, по умолчанию 1), его поля заменяют основные `needs/solves/weak/causes`, а `note` (с `{name}`) попадает в историю и раздел «Повороты».

Новые типы карт: `peek` (тайно подсмотреть характеристику, `key` — какую или `random`), `peek_goal` (узнать секретную цель), `block_reveal` (запрет раскрываться в раунде), `steal_card` (украсть карту действия), `protect` (защита игрока от голосов).

Разнообразие (`content/goals.json`, `events.json`, `relations.json`, редактируются в редакторе в группе «Разнообразие»):
- цель: `{ id, icon, title, text, kind, need? }`, `kind`: `survive`, `with`, `keep_out`, `protect` (в тексте `{target}` — случайный другой игрок), `need` (+ поле `need`), `traitor`;
- событие: `{ id, icon, title, text, effect, causes? }`, `effect.type` — как у карт (`change`, `swap`, `shuffle_all`, `reveal_target`, `bunker_reveal`, `revive`, `cancel_vote`, `immunity`, `double_vote`) плюс `none` и `extra_reveal` (`amount` — сколько доп. раскрытий); цели выбираются случайно;
- связь: `{ id, icon, title, text, together, needs?, causes? }`, в текстах `{a}` и `{b}` — имена; `needs`/`causes` действуют в финале, если оба в бункере.

Настройки лобби: `goals`, `goalsTraitor` (off/maybe/always), `events` (off/some/every), `relations` (off/few/many), `relationsPublic`. Пресеты описаны в `js/extras.js` (`PRESETS`).

Поле `when` у карты — когда её можно сыграть: `alive` (по умолчанию, только пока игрок в бункере), `any` (и после изгнания), `exiled` (только после изгнания), `auto` (срабатывает сама при изгнании владельца; цель и вариант выбираются случайно; карты иммунитета, двойного голоса и саботажа так не срабатывают).

Составной эффект (`"type": "change"`) собирается из частей:

| Поле | Значения |
|---|---|
| `op` | `add` — добавить, `remove` — убрать, `replace` — заменить |
| `object` | `trait` — характеристика игрока, `feature` — особенность бункера, `slots` — места, `food` — запас еды в месяцах |
| `key` | для `trait`: `profession`, `biology`, `health`, `hobby`, `phobia`, `baggage`, `fact`, `character` или `random` |
| `target` | для `trait`: `self` — себе, `player` — выбранному игроку, `all` — всем, `random_player` — случайному игроку |
| `mode` | для `trait` и `feature`: `random` — случайно из всей игры, `pool_random` — случайно из пула, `pool_choice` — игрок выбирает из пула, `fixed` — заранее заданное значение |
| `pool` | для `pool_*`: `{ "source": "preset", "items": [...] }` — список из существующих значений раздела (в редакторе отмечаются галочками), или `{ "source": "random", "size": 3 }` — случайный набор из игры |
| `value` | для `mode: fixed` — само значение |
| `amount` | для `slots` и `food` — сколько |
| `infinite` | для `food` с `add`/`replace`: `true` — еды становится бесконечно |

При «убрать» пул работает как фильтр: убирается только то, что есть у цели (и, если задан список, только из него).

Особые карты: `swap` (обмен характеристикой `key`), `shuffle_all`, `reveal_target`, `immunity`, `double_vote`, `cancel_vote`, `bunker_reveal`, `revive`. Старые типы (`reroll_self`, `set_target`, `extra_slot` и т. п.) по-прежнему понимаются игрой.

Если характеристике что-то добавили, значения хранятся через « + », например `Аптечка + Коза`.

## Свои наборы в лобби

Хост может загрузить архив из редактора или `.json`-файлы прямо в лобби. Набор сохраняется в Firebase в `rooms/{код}/content` и удаляется вместе с комнатой; файлы на сайте не меняются. Лимит — около 900 КБ на набор.

## Ограничения текущей версии

- Защиты от подсматривания нет: технически подкованный игрок может увидеть чужие карты через консоль браузера. Для игры среди друзей это нормально, защиту можно добавить позже.
- Старые лобби не удаляются автоматически. Они весят единицы килобайт, но при желании их можно удалить вручную в консоли Firebase (узел `rooms`).
- Голосовой связи нет — играйте параллельно в Discord или Telegram.
